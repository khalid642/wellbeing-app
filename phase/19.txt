Phase 19 — Watchdog, Crash Recovery & Polish

Build reliability systems and polish the entire app.

WATCHDOG SYSTEM:

Enhance wellbeing_app/daemon/watchdog.py:

WatchdogService:
  Runs in the same GLib main loop as the daemon (no separate thread)
  Checks every 60 seconds:
    - Were any GLib timers fired in the last 5 minutes? (track via last_event_time timestamp)
    - Is the prayer engine returning valid times? (quick sanity check)
    - Is the audio engine in a valid state?
    - Are all scheduled events still registered?
  
  If main loop appears stalled (checked via GLib.idle_add heartbeat):
    Log CRITICAL warning
    Attempt daemon restart: reload config, recalculate schedule, reregister timers
  
  Safe mode: if 3 consecutive restarts fail, enter SAFE_MODE:
    Disable all overlays
    Only play adhan (no lock screens)
    Show desktop notification: "Wellbeing App entered safe mode"
    Log reason

CRASH RECOVERY:

Create wellbeing_app/utils/recovery.py:

On app start, check ~/.local/state/wellbeing-app/crash_state.json:
  If file exists: last session crashed without clean exit
  Show non-intrusive in-app notification: "App recovered from unexpected exit"
  Offer: "View Logs" button

On clean exit: delete crash_state.json
On app start: write crash_state.json with timestamp + pid

Config backup rotation:
  Before any config write, create a backup in ~/.config/wellbeing-app/backups/auto/
  Keep last 10 auto-backups
  If config read fails (corruption): auto-restore from most recent backup
  Log restoration event

  Database: add indexes on frequently queried columns (overlays.type, widget_templates.category, reminders.enabled)
  Ensure daemon memory usage stays under 50MB at idle (profile with tracemalloc, log if exceeded)
